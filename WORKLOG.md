- **Pathology — `MorseModel.calc_atomic_energies` produces NaN gradient on padded atoms.** Surfaced while debugging the script's initial NaN-from-step-1 behaviour. Root cause: `bessel_descriptors.center_at_atoms` sets `radius = where(types<0, inf, _sqrt(...))` for padded sources. `MorseModel.calc_atomic_energies` tries to neutralise via `radii += 2 * mask * r_cut`, but `inf + finite = inf`. Then `exp(-a*(inf-b))=0` (clean forward), but `d/da[-a*(inf-b)*0] = -inf*0 = NaN` in the backward. The subsequent `smooth_cutoff` and `isclose(radii, 0)` masks multiply by 0, but NaN*0=NaN poisons `morse.embed.embedding` and `morse.switch_param` on every step. Step 0 produces a finite loss (3.73) because the forward path is clean; step 1 onward is NaN because the optimizer applied a NaN-contaminated gradient. The user's at-origin-Si frames (40 of them) are a red herring — the bug fires on every batch with any padded atom. Diagnosis by `jaxrens-debugger` agent in `<5 min` via a Morse-only synthetic-radii bisect: all-real radii → clean grad; inject `inf` → `embedding=NaN, switch_param=NaN`; replace `inf` with `100.0` finite → clean grad. New pathology memory at `.claude/agent-memory/jaxrens-debugger/pathology_neuralil_morse_padded_inf_nan.md`.
  - **Fix applied (training-script-level, no upstream edits):** monkey-patch `MorseModel.calc_atomic_energies` at import time to `radii = where(isinf(radii), 2*r_cut, radii)` before delegating to the original.
